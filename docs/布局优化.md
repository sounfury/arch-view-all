# 工作台布局优化：紧凑代码图与右上角全局架构 Pin

<!-- 职责：定义代码主画布的自适应布局、缩放策略与右上角架构导航浮层，作为下一轮网页体验优化的实现与验收依据。 -->

**状态：三个阶段都已实现。** 主图按候选列数排布，默认可读比例，适应全图改为显式操作；全局架构改为右上角浮层。工具栏收成一行，空详情栏默认收起，包树合并已加载的无分叉前缀。浮层默认尺寸仍可按浏览器验收微调。

**范围：** `arch-view serve` 网页工作台。本文基于 `29fb06d` 的实现与实际使用截图；不改变 CLI、静态分析、文档绑定、trace/note 格式或 AI 安全边界。

**关联：** [探索导航与全局定位](navigation-ux-stories.md)、[随身 AI 助手 PRD](ai-companion-prd.md)。本文提出对 US-3 的后续布局调整：以右上角浮层取代默认上下分屏；US-3 原有定位、来源选择、代码跳转和状态隔离契约继续保留。实现前仍以现有行为为现状，不能把本文的目标当成已实现。

## 1. 问题与结论

用户需要同时掌握业务全局和阅读当前代码结构。全局架构应继续 pin，但不需要在其中展开软件包；进入模块、包和文件仍发生在代码依赖主图。

当前截图的主要问题不是物理屏幕不够，而是空间分配与图布局不匹配：

- 全局 pin 占用整行高度，却不需要与代码主图同等面积。
- 主图有大量横向留白，节点仍被整体缩小，造成“空白很多、内容很挤”。
- 工具栏和未使用的详情栏长期占位；包树的公共前缀形成很深的低信息层级。

源码中可确认的直接原因：

- `app.js / canvasColumns()` 将列数固定为最多 3 列。
- `positionsFor()` 先按固定列数排布，再计算整图尺寸；列间步长为 272、行间步长为 178，另有外边距和层间距。
- `fitMap()` 同时适应宽高并取较小比例；节点较多时，窄长布局被高度限制进一步缩小。
- `app.css / .pinned-architecture` 默认占主面板约三分之一高度、至少 220px，进一步压缩代码图高度。

截图中“约一半画布没有有效利用”是用户观察，不是浏览器测量结果。实施时须补充实际尺寸和缩放数据，不能用主观百分比替代验收。

**核心决策：先改善图的形状，再调整相机；让代码图成为唯一主画布，全局架构以右上角业务导航浮层常驻。不能靠缩小字号或卡片解决问题。**

## 2. 目标与非目标

### 2.1 目标

1. 保留全局架构 pin 和既有代码下钻路径。
2. 让代码图布局适应主画布的宽高，不再在宽画布中固定排成窄长三列。
3. 默认优先可读，提供显式“适应全图”，不要求每次都把所有内容缩进一屏。
4. 左树、详情、AI 面板和 pin 同时存在时，仍有明确的主画布与操作焦点。
5. 显著降低由布局造成的无效留白，但不以填满所有像素为目标。

### 2.2 非目标

- 不在架构 pin 中实现包展开、文件树或第二套代码下钻。
- 主代码图的单击选中、双击下钻语义不变，不重写 `locateModule` 导航；pin 按下述交互直接进入覆盖代码。
- 不把业务数据流当作静态代码依赖，不新增不存在的边。
- 不为了填充画布打乱依赖层次、拉伸卡片、缩小正文或强制放大少量节点。
- 不重新设计 AI 对话流程或并行引入第二套悬浮聊天窗口。
- 不增加新图库、构建工具；不要求手机适配。

## 3. 工作区结构

```text
┌─────────┬─────────────────────────────────────────────┐
│ 模块树  │ 面包屑 / 搜索 / 主图工具栏                   │
│         ├─────────────────────────────┬───────────────┤
│         │                             │ 全局架构  📌  │
│         │                             │ 紧凑导航图    │
│         │       代码依赖主画布        └───────────────┤
│         │                                             │
│         │                                             │
└─────────┴─────────────────────────────────────────────┘
                         详情 / AI 按需在右侧打开
```

- pin 锚定在主画布内容区右上角，不放在整个浏览器窗口右上角，不盖住顶栏或主图工具栏。
- 默认不再为 pin 预留整行，也不为它划出贯穿整屏的空白列。
- 右侧详情或 AI 面板打开后，pin 跟随主画布实际右边界移动，不覆盖面板。
- 主画布是唯一的代码探索操作区；鼠标位于 pin 时，拖动/滚轮只操作 pin，不传递给主图。

## 4. 全局架构 Pin

### 4.1 保留既有行为

保留项目级文档数据流优先、无可用数据流时回退根层代码架构；包级文档不替换 pin 来源。来源、关闭状态、全屏、重新分析、异步失效保护等规则沿用现有实现。

手势按后续使用反馈调整：

- **单击节点：** 显示摘要，并直接在代码依赖主图进入该节点绑定的全部代码范围。
- 不再提供代码范围选择框、“进入代码”按钮，也不因 pin 点击创建临时返回入口。可通过主图面包屑和模块树继续导航。
- 不在 pin 内把业务节点替换成包或文件；回退来源为根层代码架构时，同样只在主图下钻。
- 外部系统与无有效绑定节点仅显示说明，不改变代码图。
- 多代码落点一次展示全部有效绑定范围；重叠范围去重，依赖边仍取源码分析结果。

### 4.2 大小与状态

以下是首轮实现的建议默认值，需要浏览器验收后调整，不是固定产品限制：

| 状态 | 行为 |
| --- | --- |
| 钉住 | 默认宽约 360px，高度通常不超过主画布的三分之一；拖动左缘调整宽度，拖动左下角同时调整宽高，并按视口变化同步缩放图形。最小约 320×168px，最大不越出主画布，手动尺寸按项目记忆 |
| 放大阅读 | 扩大到主工作区，同时提高节点和文字的实际屏幕尺寸，文字目标至少 18px，显示完整说明和边标签；大图允许平移阅读，“适应”仍为显式操作；退出后还原主图及 pin 相机 |
| 收起/关闭 | 仅保留右上角重新开启入口；按项目保存偏好 |

当主画布不足以同时容纳可读 pin 和代码图时，优先收成可展开入口或由用户选择放大，不继续无限缩小标签。窗口变化不能产生负尺寸或把按钮挤出可操作区。

旧的上下分屏高度偏好不直接套用为浮层尺寸；首次迁移使用新默认值，保留来源和关闭偏好。

### 4.3 紧凑呈现，不丢数据

不能仅将完整 Mermaid SVG 按比例缩小后宣称它是可用小地图。

- 常驻态优先短业务名称，完整标识、职责、状态和边含义在悬停/聚焦或选中后展示。
- 连线标签可在紧凑态隐藏，但节点和边的数据不得删除或改变；放大态显示完整信息。
- 不复制一份需要人工维护的简化架构文档。紧凑呈现必须派生自同一份解析结果；原始 Mermaid 保留为完整阅读来源。
- 对无法安全简化的 Mermaid 样式或节点类型，保留原图并提供放大阅读，不用脆弱的字符串替换破坏语义。
- 根层代码架构回退也使用短名称与完整详情，不展示下钻展开按钮。
- 业务图没有与代码图一一对应的坐标，禁止用“视窗矩形”假装表示代码当前位置。

当前业务位置、最近进入点、多归属和未归属继续采用原有映射结果。代码下钻时只更新高亮，不重新排布 pin，保持地图位置稳定。

连线按阅读焦点呈现：

- 小浮层默认仅展示代码当前位置对应节点的直接上下游，橙色表示上游输入，绿色表示下游输出；其余节点保留作全局参照。
- 悬停或键盘聚焦其他节点时临时预览其直接关系，离开后恢复代码当前位置。预览不触发导航、重排或修改主图相机。
- 项目根层尚无当前位置时，提示悬停查看上下游；点击无绑定节点仍可查看它的关系和说明。
- 放大阅读中可切换“全部连线”，完整展示所有关系和边标签；退出放大后恢复紧凑聚焦模式。
- 紧凑图仅调整同层顺序以减少交叉，分配独立出入口和走线通道，回边走外围。节点、端点、方向、标签和边数量保持原数据。
- 无法可靠识别端点的特殊 Mermaid 图保留原图连线，不通过过滤产生残缺关系。

### 4.4 遮挡处理

浮层不等于允许任意遮挡关键内容：

- 在“定位当前节点”、跳转与初次选中聚焦时，将 pin 矩形视为遮挡区，保证目标卡片和主要标签可见。
- 不把整个右侧都认定为不可用，避免重新制造贯穿高度的空白。
- 拖动主画布允许内容经过浮层下方；用户可收起 pin 或再次定位，不要求所有时刻零遮挡。
- 弹出菜单、源码抽屉、AI 面板的层级与焦点高于 pin；放大 pin 关闭后恢复此前焦点。

## 5. 代码图紧凑布局

### 5.1 自适应列数，而不是固定三列

将 `canvasColumns()` 的固定上限改为基于容器尺寸与节点分组的候选布局选择。

首轮采用确定性、有限候选计算，不要求引入复杂全局图优化：

1. 取得实际主画布宽高、卡片尺寸、节点依赖层及当前显示边。
2. 按实际宽度和最小卡片间距生成可行列数，不再固定最多三列。浏览模式默认不靠缩小卡片来增加列数。
3. 分别计算候选布局的包围盒、默认可读比例下的溢出、层间连线通道和横向利用情况。
4. 排除节点重叠、路由越界和严重破坏层次的候选。
5. 优先选择无需不可读缩放、横向溢出少、纵向滚动较短的候选；结果接近时保留当前列数，避免抖动。

现有依赖层排序继续生效；同层可多列排列，不同依赖层仍保持方向。有环节点保留已有环信息，不能通过重排伪装成无环。

少量孤立节点紧凑排布，不强行铺满；大量孤立节点允许规则网格。任何因路由需要保留的留白都应与实际边相关，而不是一律占用大边距。

### 5.2 间距和边界

- 首轮保留当前卡片正文和点击区域尺寸，不以缩字作为优化手段。
- 将外边距、层间距、同层间距提为布局参数；分别依据卡片和路由需要调整，不统一压成零。
- 布局尺寸依据节点及实际连线路由的并集计算，包含必要的标签外延；不只裁节点，避免裁断绕行边。
- 改列数后必须检查 `routeEdge()` 的同层、跨层、远端绕行路径；不能只改 CSS 网格而沿用错误坐标。
- 同一数据和容器尺寸得到稳定顺序；选择节点不触发重排。

### 5.3 默认相机与显式适应分离

| 场景 | 策略 |
| --- | --- |
| 首次进入新代码层级 | 默认可读比例约 100%，充分利用宽度；节点多时允许纵向滚动 |
| 内容小于可用区域 | 正常尺寸呈现，不强行放大填满 |
| 用户点击“适应全图” | 显式按宽高共同缩放，可低于默认可读比例；显示缩放百分比 |
| 用户缩放/平移后 | 保留用户相机，不因普通点击或详情更新自动复位 |
| 返回上一层/关闭源码/退出 pin 放大 | 恢复原路径和相机，避免再次执行全图适应 |
| 容器尺寸变化 | 在确需变列时重新布局，并优先保持选中节点的可见性及相对位置；不因几像素变化反复重排 |

“适应全图”和“恢复可读比例”要有明确区别，可用简短按钮或菜单提供，不再堆叠多个含义相近的常驻按钮。

## 6. 周边空间优化

本节作为后续阶段，不阻塞主图与 pin 调整：

- 合并代码区标题、说明和操作为紧凑工具栏；低频操作进入菜单，保留清晰的当前路径和缩放状态。
- 未选中任何模块、也没有固定详情/AI 会话时，右侧提示不应占完整常驻栏；允许收起并由选择操作重新打开。
- 用户主动固定的详情或 AI 会话不因取消选择自动关闭。
- 导航树合并无分叉公共包前缀，完整路径仍可查看和复制；构建模块边界不可合并掉。
- 合并后的树节点保留原有按需加载和导航行为，不为压缩前缀一次请求全仓。

## 8. 验收标准

### 8.1 样例与记录

使用已有的 15 节点、24 边业务数据流夹具，以及根层 Maven 模块图和类似当前 `impl` 的多包场景。分别验证少量节点、同层多节点、多依赖层、环、长标签、无绑定节点。

建议浏览器视口：1440×900、1920×1080；同时记录浏览器缩放及 devicePixelRatio，避免将截图缩放误判为产品字号问题。对每个用例记录主画布实际宽高、列数、布局包围盒和默认 zoom。

### 8.2 必须通过

| 编号 | 条件 |
| --- | --- |
| A1 | pin 常驻右上角，不再预留横跨主区的顶部一整行；打开/关闭不把主图高度切成上下两块 |
| A2 | pin 单击即进入全部有效绑定范围，无目标选择框和进入按钮；任意代码下钻都只改变主图，pin 不展开包 |
| A3 | 具备放置四列及以上正常尺寸卡片的宽度，且同层节点足够时，算法实际评估并可选择超过三列，不再被旧上限锁死 |
| A4 | 对本次窄长图回归样例：若候选宽布局可在正常比例下减少纵向溢出，不得仍固定三列再因高度不足自动缩到 73% 或更低 |
| A5 | 首次进入密集代码层级以可读比例呈现，可滚动；点击“适应全图”后才执行整图缩放，并明确显示缩放状态 |
| A6 | 节点无重叠，连线及标签没有因尺寸裁剪丢失；依赖层和环标记未被篡改 |
| A7 | 定位或跳转到的选中卡片不落在 pin 遮挡区；右侧面板打开后 pin 不覆盖其操作 |
| A8 | 返回上一层、退出放大阅读、切换右侧面板后，不无故丢失路径、选择与手动相机状态 |
| A9 | pin 紧凑态隐藏的文字可在完整阅读或详情中找回；原数据流节点、边及含义没有丢失 |
| A10 | 单纯选择节点不重排；窗口连续 resize 不出现无限循环、明显抖动或大量重复请求 |

不以“节点面积必须占画布百分之多少”作为单一硬指标：稀疏图和依赖通道需要合理空白。验收重点是消除三列上限、无意义外边界和自动缩小造成的低效，不是把关系图塞满。

## 9. 分期与回退

1. **第一阶段：主图布局和相机。** 修复固定三列、默认全图缩小，建立回归截图与尺寸记录。
2. **第二阶段：右上角 pin。** 替换默认上下分屏，补紧凑展示、遮挡处理、偏好迁移和放大恢复测试。
3. **第三阶段：周边密度。** 工具栏、空详情栏和包树前缀压缩，分别验收，避免一次改变全部导航习惯。

上线前比较相同数据、相同视口的新旧截图。旧布局偏好和新浮层偏好分开存储，便于回退；不删除用户架构文档、notes、traces 或 ACP 会话。

## 10. 已确定与待验证

**已确定：** 全局架构继续 pin；推荐右上角浮层；pin 不展开包；保留既有代码跳转手势；主图紧凑化不能只靠缩放和缩字。

**待浏览器验证：** 浮层默认宽高、各类依赖图的候选布局偏好、紧凑标签的可读阈值及边路由所需间距。上述参数不能凭截图一次定死，也不应据此扩大为全站重设计。
