# PRD：架构图上的随身 AI 助手

<!-- 职责：约定网页 AI 从「模块详情里的解释按钮」改为「项目级随身助手」的产品目标、范围、分期与验收，供实现与核对使用。 -->

**状态**：草案  
**范围**：仅网页工作台（`arch-view serve`）。桌面端、CLI 的 `query` / `context` / `trace` / `notes` 契约不改。  
**相关**：实现数据格式仍以 [AI 辅助探索设计契约](ai-exploration.md) 为准；本文管交互与能力，不替代那份契约。

---

## 1. 背景与问题

Arch View 的差异化是：**静态图画事实，AI 做解释，解释能指回图和源码，并能保存、过期检测。**  
当前网页把 AI 做成「点开一张模块卡片 → 详情里点『让 AI 解释』→ 抽屉里问答」。图、锚点、笔记是事后贴上去的，不是助手的工作方式。

现状具体问题：

| 现象 | 原因 |
| :--- | :--- |
| 对话像一次性弹窗，不像随身助手 | 聊天住在与源码/文档共用的抽屉里；会话按模块隔离 |
| Markdown 像没渲染 | 完成后走 `marked`，流式是纯文本；工具输出的路径墙盖过正文 |
| 一长串文件路径，点不了、跳不了 | 只把行内 `` `path:line` `` 做成链接；点链接会 `openDrawer` 换掉对话界面 |
| 讲解时图不会动 | AI 只有沙箱里的 `read/grep/find/ls`，不能聚焦模块、打开源码、高亮链路 |
| `@` 加上下文不存在 | 每次提问只自动带当前卡片的上下文包，不能从地图把其它模块/文件追加进同一轮对话 |

不要用「网页里塞一个 pi 终端」来回避这些问题。终端复用的是 TUI，接不上图、引用和只读探索；助手要的是引用和图操作。

---

## 2. 目标与非目标

### 目标

1. 用户在看图的同时，身边有一个**不关就不丢**的项目级对话。
2. 从图上指认模块/文件（右键或「问 AI」）等于往对话里加入 `@` 附件，而不是新开一套会话。
3. 回答是可读的 Markdown；路径、模块名、`path:行号` 可点，且**不关闭对话**。
4. 讲解过程中，AI（或回答里的结构化块）能让地图聚焦、打开源码预览、临时高亮一条链路。
5. 对话、笔记、链路三种资产职责分开：探索过程可丢；认可后才写入 `.arch-view/`。

### 非目标

- 不在网页里嵌 PTY / 完整 pi TUI。
- 不把 Arch View 做成可改仓库的 IDE；默认仍是只读沙箱。
- 不自动把每轮对话写成 note/trace。
- 不在本期做 Claude/Codex ACP（协议预留即可）。
- 不改桌面端。
- 不为「看起来像 ChatGPT」而重做整站视觉。

---

## 3. 产品原则

1. **左键看结构，问 AI 是附加动作。** 单击仍是选中与详情；双击仍是下钻。不要抢走现有地图手势。
2. **一个项目一个主对话。** 换模块是往当前对话加上下文，不是换一条聊天线程。用户仍可「新建对话」。
3. **图是工作台，聊天是旁白。** 源码预览从属于助手或详情，不得覆盖聊天 DOM。
4. **引用先于工具，工具少而尖。** 先让人点得动；再让模型驱动地图。不做通用 shell。
5. **静态事实优先。** 上下游、路径、环继续以分析图为准；模型推断必须可识别。
6. **保存是发布。** 对话是草稿；笔记和链路是过了你认可、绑锚点、能随仓库提交的知识。

---

## 4. 目标体验

主工作区保持「地图 + 详情」，增加**常驻助手栏**（地图右侧第二栏，或详情下方可拉高的底栏；窄屏可把详情与助手做成标签）。关闭助手栏后，布局与现在一致。

典型路径：

1. 打开工作台，助手栏空闲，显示「在图上右键模块，或输入 @ 加入上下文」。
2. 右键 `arch-view.web.model` →「问 AI」：输入框出现芯片 `@web.model`，焦点进入输入框。
3. 用户问「它和 server 怎么连」；再点另一个节点「加入对话」，芯片变成 `@web.model` `@web.server`。
4. 回答以 Markdown 流式出现。文中 `src/arch_view/web/model.clj:40` 是芯片，点击后**旁边**打开源码并滚到该行；模块名芯片会选中地图节点并滚动到可见。
5. 模型（或解析出的链路块）调用「高亮路径」：图上临时画出 model → server，详情仍可看，聊天还在。
6. 用户点「保存为解释」：自动带上本轮 `@` 目标与文中引用锚点，写入 notes；或「另存为链路」把临时高亮变成 trace。

## 5. 功能需求

### 5.1 布局与会话（P0）

| ID | 需求 | 验收 |
| :--- | :--- | :--- |
| L1 | 助手为常驻面板，不使用与源码/文档共用的 `#drawer` 作为主聊天容器 | 打开源码或架构说明时，聊天 DOM 仍在，历史不丢 |
| L2 | 会话默认按**项目**计，不按模块 Map 隔离 | 从 A 问到 B，同一 `sessionId` 续聊；历史列表也不再按 target 切开（若后端仍存 target，取「当前项目」即可） |
| L3 | 提供新建对话、恢复历史、停止回答、模型/思考强度下拉（沿用现有 ACP configOptions） | 行为与现在抽屉内一致，只是换到常驻栏 |
| L4 | 未配置 `pi-acp` 时仍可复制上下文包；配置后自动 `open` 会话 | 不配置不 500；复制对象改为当前 `@` 集合，空则复制当前选中模块 |
| L5 | 源码预览：助手内分栏，或详情区切到源码；关闭预览回到详情 | 预览不得 `replaceChildren` 掉聊天 |

### 5.2 入口与 @ 附件（P0）

| ID | 需求 | 验收 |
| :--- | :--- | :--- |
| A1 | 节点右键菜单：「问 AI」「加入对话」 | 问 AI = 加入并聚焦输入框；加入对话 = 只加芯片。左键行为不变 |
| A2 | 详情「AI 解释」区保留已保存 notes 列表；主按钮改为「问这个模块」（等价右键「问 AI」） | 不再打开抽屉作为唯一入口 |
| A3 | 输入框支持芯片：`@模块` / `@路径`；可点 × 移除；可键入 `@` 搜索模块与文件 | 芯片有稳定 id（规范模块名或相对路径） |
| A4 | 发送时把芯片解析为附件：每个目标生成现有上下文包（可截断），随本轮 prompt 交给模型 | 未 @ 任何东西时：若有当前选中节点则默认带上；都没有则允许纯追问（不强制灌全仓） |
| A5 | 提示词要求引用格式：`` `相对路径:行号` ``，模块用规范名；禁止把 grep 结果整表贴进回答 | 抽检回答以叙述+引用为主，而不是路径墙 |

### 5.3 渲染与引用（P0）

| ID | 需求 | 验收 |
| :--- | :--- | :--- |
| R1 | 流式过程也按 Markdown 渲染（允许节流）；完成后与 notes 同一套 `richText` | 标题、列表、代码块可见，不是一整块 `pre-wrap` |
| R2 | 识别并做成可点芯片：`` `path:line` ``、`` `path:start-end` ``、相对路径、已分析模块名 | 不依赖必须包在 code 标签里；误伤普通英文单词时宁可漏不要乱链 |
| R3 | 点路径芯片 → 源码预览定位行；点模块芯片 → 地图选中、滚动、详情切换 | 聊天面板仍在 |
| R4 | 工具调用过程显示短状态（「正在读 model.clj」），不要把工具原始 JSON/路径列表当作正文 | 正文区只有 assistant 文本；工具是次要状态行 |
| R5 | `richText` 对非 http 链接不再直接剥掉：项目内路径按芯片处理 | 模型写的 Markdown 链接也能跳 |

### 5.4 驱动地图（P1 解析块，P2 真工具）

先做**前端解析约定块**，不依赖 pi-acp 的 MCP（当前未完整接通）。协议稳定后再升级为 ACP/MCP 工具。

约定回答中可出现：

````markdown
```arch-view
{"action":"highlight_path","modules":["arch-view.web.model","arch-view.web.server"]}
```
````

支持的 `action`：

| action | 参数 | 界面效果 |
| :--- | :--- | :--- |
| `focus_module` | `module` 或 `target` | 选中、滚入视野、刷新详情 |
| `open_source` | `path`，可选 `line` | 打开源码预览 |
| `highlight_path` | `modules`（有序） | 复用现有 trace 叠加：临时序号与连线，**不写盘** |
| `clear_highlight` | 无 | 去掉临时叠加 |

P1 验收：模型或用户粘贴上述块后，界面执行对应动作；用户可「清除高亮」「另存为链路」。

P2 把同样四个动作做成模型可调工具（外加只读 `query_graph`：deps/rdeps/path，返回结构化短列表）。工具必须：

- 只影响本机 UI 与已有 query API，不写项目源码；
- 参数经 `workspace/resolve-target` / 路径规范化，失败则工具返回错误，不抛到整轮；
- 数量少：禁止通用 `eval`、禁止任意 DOM。

### 5.5 笔记与链路（P1）

| ID | 需求 | 验收 |
| :--- | :--- | :--- |
| N1 | 「保存为解释」使用：标题来自问题摘要；`targets` = 本轮 `@`（空则当前选中）；`anchors` = 文中成功解析的 path:line（可扩一行上下文） | 不再只绑「打开抽屉时的那一个 target」 |
| N2 | 详情里的 notes 列表、过期徽章、点锚点打开源码（走预览，不毁聊天）保持 | 与现契约一致 |
| N3 | 临时 `highlight_path` 可「另存为链路」：步骤 = 模块序列，缺锚点时 `unanchored`，走现有 `trace save` / 校验 | 不自动保存 |
| N4 | 侧栏已有 traces 仍从公共上层展示；临时高亮与已保存 trace 互斥显示，同时只显示一套叠加 | 避免两套线叠在一起说不清 |

## 6. 与现系统的边界

```text
对话（内存 + ACP 快照，不进仓库）
  ├─ @ 附件 → 现成 context pack
  ├─ 引用芯片 → 源码预览 / 地图聚焦
  ├─ 临时高亮 → 可另存 trace
  └─ 保存为解释 → notes（进 .arch-view/）

静态图 / query / 只读沙箱 / ACP 传输
  继续作为后端能力，不因 UI 改写协议
```

| 对象 | 生命周期 | 写盘 |
| :--- | :--- | :--- |
| 对话 | 项目级，可丢、可恢复 | 仅本机 `ARCH_VIEW_AGENT_STATE_DIR` |
| 临时高亮 | 当前页，换对话或清除即没 | 否 |
| note / trace | 项目知识 | `.arch-view/`，可提交 |

---

## 7. 约束

- 继续强制只读系统沙箱；隔离失败 503，不降级。
- 不新增第三方应用依赖；Markdown 继续用已有 Marked + DOMPurify。
- Clojure 函数复杂度 ≤ 12；前端保持原生 ES 模块，不引入打包器。
- 网页仍只监听本机。助手不是远程 shell，不暴露 PTY。
- 模型列表、思考强度仍来自 ACP `configOptions`，不在网页里发明一份模型目录。

## 8. 分期

**P0 — 能看、能点、能接着问（本 PRD 主交付）**

- 常驻助手栏 + 项目级会话
- 右键 / 「问这个模块」+ `@` 芯片
- 流式 Markdown、引用芯片、源码预览不毁聊天
- 工具原始输出不当正文

**P1 — 能指着图讲**

- ` ```arch-view` ` 块：focus / open / highlight / clear
- 保存解释带上 `@` 与引用锚点
- 临时高亮另存为 trace

**P2 — 模型自己拨方向盘**

- 将 P1 动作升级为可调用工具，加 `query_graph`
- 视 pi-acp MCP/自定义工具进展接入；未接通前不阻塞 P0/P1

## 9. 成功标准

做完 P0 后，用本仓库走通：

1. 不点详情按钮，只在图上右键 `arch-view.web.model` → 问「职责和谁依赖它」→ 回答有标题/列表，不是路径墙。
2. 点击回答里的 `src/arch_view/web/model.clj:行号` → 源码出现且聊天仍在；再点模块名 → 地图选中该节点。
3. 再右键 `arch-view.web.server`「加入对话」追问关系 → 同一会话，两次 `@` 都在芯片栏。
4. 打开已有 note 的锚点，同样不关掉聊天。

P1 额外：回答或手动块能高亮 model→server，清除后线消失；另存后侧栏出现该 trace。

## 10. 明确不做（本期）

- 网页终端、把 pi 的全屏 TUI 嵌进来
- 多 agent 并列、对话里改代码、自动 commit
- 让模型任意执行前端脚本
- 为每个模块默认开一条 ACP 进程（改成项目级后，同时活动会话上限仍可沿用现有 4 条，避免沙箱进程膨胀）

## 11. 待决（实现时可定，不挡 P0）

- 助手栏默认在右侧第二栏还是地图下方：优先右侧，窄屏用标签切「详情 / 助手」。
- `@` 搜索是否包含未分析文件：P0 只允许已分析模块 + 其源码路径。
- 无 `@` 且无选中时是否禁止发送：允许发送（纯追问）；首次打开可提示去图上指一个模块。
- 流式 Markdown 节流间隔：以不明显卡顿为准，不必逐 token 重解析。
