## 1. 背景与现状

工作台已经能从根层下钻到源码，Java/Kotlin 多模块项目会按 Maven/Gradle **构建模块**当根节点。但「我现在在哪、这一支怎么连、怎么回到宏观」还靠面包屑和切视图：

| 现象 | 现状 |
| :--- | :--- |
| 左侧「模块导航」像一层快捷入口，不像工程树 | **已实现（US-1）**：侧栏按构建模块/包路径展开为文件夹树；点三角只改树，点名称才导航。无构建模块时同样按包路径展开 |
| 选中一个源码文件，只能看见一跳邻居 | 单击高亮当前节点的直接上下游；完整路径要自己切「全部模块」、开已保存的 **调用链路**，或去 CLI 跑 `query deps` / `rdeps` / `path` |
| 下钻后宏观图消失 | 主画布被当前层替换。文档数据流和代码依赖抢同一块主图（`代码依赖` / `文档数据流` tab），看一个就必须关掉另一个。数据流节点已能点击跳到对应模块（`locateModule`） |

原则与现产品一致：**左键看结构，双击下钻；静态事实优先；不抢走现有手势。** 优化是补定向，不是重做整站。

## 2. 用户故事

### US-1 构建模块导航做成可展开的文件夹树

**作为** 阅读 Java / Kotlin 多模块仓库的人，  
**我希望** 左侧模块导航按「构建模块文件夹 → 包 → 源码文件」展示，并能展开/收起，  
**以便** 不靠主图层层双击，也能在工程边界里定位到某个包或文件。

适用于分析时识别出 Maven/Gradle **构建模块**的项目（见 `ARCHITECTURE.md` 中 input 的「构建模块发现」）。没有构建模块的 Clojure / Python 项目同样按包路径做成可展开树。

**不是**：把导航变成操作系统文件树（不列出 `src/test`、构建产物、隐藏目录）；展开不等于自动把主图切到那一层——展开是看目录，点击名称才导航。

| ID | 需求 | 验收 |
| :--- | :--- | :--- |
| N1 | 根层节点是构建模块，样式像文件夹/模块，带已有立方体图标与 Maven/Gradle 标签、模块目录 | 多模块 Java/Kotlin 项目打开后，导航第一层是 `user-api` 这类模块，而不是直接铺开全部包 |
| N2 | 每个非叶子可展开/收起；展开后显示该模块（或包）下一层子包与同层文件 | 点三角只改树，不切换主图路径；点名称仍走现有 `navigate` / 选中叶子 |
| N3 | 当前主图路径、选中节点在树中高亮，并滚入可见 | 从地图双击进入 `user-api/.../Port` 后，树自动展开祖先并标 `current` |
| N4 | 子层按需加载（复用 `/api/view?path=` 与视图缓存），不要一次拉全仓树 | 只展开过的分支发请求；失败时该节点可重试，不把整栏清空 |

### US-2 叶子模块的全链路，一张图看完

**作为** 盯着某一个源码模块（叶子节点）的人，  
**我希望** 一键把「谁用到它、它又依赖谁」画在同一张图里，  
**以便** 不用自己在一跳高亮和已保存链路之间拼出这条模块的位置。

「单代码模块节点」= 地图上的叶子（直角卡片 / 源码文件），不是构建模块或包聚合节点。包节点继续下钻，不自动出全链路。

**不是**：替代 `.arch-view/traces/` 里人工/AI 保存的调用链路；那些仍是带锚点、可校验的叙事。全链路是**静态图上的切片**，默认不写盘。可提供「另存为链路」（走现有 `trace save`），但这是附加，不是本故事的 P0。

| ID | 需求 | 验收 |
| :--- | :--- | :--- |
| C1 | 选中叶子后，详情提供「全链路」入口（按钮或图模式），打开后主图只保留与该模块相关的节点与边 | 未选叶子不出现该入口；打开后能一眼看到该模块及其上下游，而不是整层包图 |
| C2 | 链路内容来自已有静态查询，不发明运行时调用：下游 `query deps`、上游 `query rdeps`，可选画出从若干入口到该模块的 `query path` | 节点、边、环标记与代码依赖图一致；图上没有的边不要画成实线 |
| C3 | 默认深度有上限（建议上游/下游各 2，或合计节点上限），超出时注明「还有 N 个未画出」并可「再展开一层」 | 中心模块（被大量引用）不会把全仓倒进一张图导致卡死 |
| C4 | 仍可单击看详情、双击打开源码；点图上其它模块可把「中心」换成它并重算切片 | 手势与代码依赖图一致；切中心不丢失「退出全链路、回到当前包视图」 |
| C5 | 与已保存 trace 互斥显示：同时只叠加一套强调线 | 打开全链路时收起 trace 高亮，反之亦然，避免两套序号 |

### US-3 钉住一份全局架构，始终标出「你在哪」，且可点回去

**作为** 已经下钻进某个包或源码文件的人，  
**我希望** 始终能看见一份钉住的宏观图，并高亮我当前所在的宏观模块/数据流节点，  
**以便** 不靠面包屑回忆「我从哪条业务链路走进来的」，并能直接点宏观节点跳走。

**已确认方案**：默认钉住**项目级文档数据流**；没有可用数据流时使用**根层代码架构**。只支持这两种来源，可切换、可关闭，按项目记住关闭状态与来源偏好。包级文档不成为 pin 来源；不做窄屏适配。

钉住图放在主工作区上方，与下方代码图上下分屏，参与正常布局，不浮盖代码卡片；可拖动分隔条调整大小。钉住时，下方以代码图为主，不重复提供互斥的数据流 tab；关闭后恢复原有 tab，并保留重新开启入口。

大型数据流必须保留完整节点、边和标签，支持独立缩放、平移、适应画布及「放大阅读 / 返回分屏」。常驻区域负责宏观定位，不承诺小比例下所有标签均可读。位置变化只更新标记，不重新排版或强制把视口拉回；提供「定位当前」。

| ID | 需求 | 验收 |
| :--- | :--- | :--- |
| P1 | 首次进入默认开启；优先项目数据流，无数据流回退根层代码架构 | 同时显示宏观图与当前代码图；关闭后可重开，刷新保留项目内偏好 |
| P2 | pin 独立保存项目级文档与画布状态 | 下钻到有包级 `ARCHITECTURE.md` 的目录，pin 来源不变；重新分析后更新数据 |
| P3 | 大图拥有独立缩放、平移、适应、分隔条及放大阅读操作 | 以 15 个节点、24 条边的业务数据流验收；返回分屏不丢代码图的浏览位置 |
| P4 | 标记当前宏观位置与最近一次进入点 | 查看源码优先于选中节点，未选中时使用当前包；进入共享模块后，当前位置与原业务进入点可以不同 |
| P5 | 按已有文档绑定与覆盖范围做反向定位 | 路径边界匹配，优先具体绑定；多节点归属明确标出，无映射明确提示，不根据名称相似度猜测 |
| P6 | 单击查看 pin 节点信息；双击或「进入代码」复用 `locateModule` | 有效绑定可以跳转，外部系统和无绑定节点不提供代码跳转；可回到跳转前的位置 |
| P7 | pin 跟随地图全屏，高亮独立于主图的选中与 trace | 不复制 trace 编号、不自动强调数据流边；放大 pin 后可返回分屏 |
| P8 | 数据流读取或渲染失败不阻断代码探索 | 显示错误与重试或根层代码图入口；过期异步结果不覆盖新来源 |

大图验收样例保存在 [业务数据流夹具](../spec/browser/fixtures/us3_business_flow.mmd)，保留用户提供的 15 个节点、24 条边及原始标签；[浏览器验收](../spec/browser/us3_pin_test.cjs) 使用真实临时项目、HTTP 服务和 Chromium 检查双画布导航。

不做「设计边 ∩ 代码边」自动叠图。两张图用于人工对照，不做自动边 diff。

## 3. 三者如何配合

```text
左侧：构建模块树（US-1）
主图：当前层代码 或 叶子全链路（US-2）
钉住：全局架构 / 数据流，高亮当前宏观位置，可点跳转（US-3）
```

## 4. 非目标

- 不改桌面 Quil 窗口。
- 不把导航改成可编辑的工程视图，也不扫描测试源码或 `build/`、`target/`。
- 不在全链路里用 AI 补「静态图没有的调用」；推断必须可识别，且默认不要。
- 不自动把全链路写成 trace/note。
- 不为此引入打包器或新的图库。
- 不替代 [随身 AI 助手 PRD](ai-companion-prd.md) 的常驻对话。
- 不做设计数据流与代码依赖的自动边 diff。
