# 网页读取规则

## 文件头说明

模块卡片与源码详情会自动读取文件开头的说明：

- 文件最前面的 `;`、`#` 注释行；
- 开头的 `/* */` 或 `/** */` 块注释，须在 `package`、`import` 之前（Java、Kotlin 用这种）；
- Python 模块文档字符串；
- Clojure `ns` 文档字符串。

`//` 行注释不读取，版权、许可证和编码声明会被忽略。目录只有一个源码文件时沿用该文件的说明；`ARCHITECTURE.md` 中绑定的子系统职责优先显示。

新建文件或职责变化时，在文件头用一两句话写明职责，图才会更易读。整理老项目时，列出缺少说明的关键文件供用户决定是否补写，不擅自批量改业务代码。

## 包级架构文档

大包需要单独说明内部结构时，可在该包目录放一份按模板编写的 `ARCHITECTURE.md`：

- 子系统标题和 `#module=` 链接相对该包目录填写；
- `## 数据流` 写包内数据流。

网页进入该包（或更深的目录）时自动改用最近的包级 `ARCHITECTURE.md`，图上的子系统名、职责、实现状态和文档数据流都随之切换，回到上层后恢复项目文档。包内 `README.md` 不会被识别。代码依赖视图下左侧导航始终用项目级文档；数据流视图下左侧列出当前文档的数据流节点。

只在用户要求或包内结构确实复杂时才建包级文档。

## 函数复杂度

本机装有 crap-everything 的 `crap` 命令（`uv tool install` 安装）时，`serve` 会在后台运行 `crap complexity`：只算圈复杂度，不运行测试，不在项目里写文件。支持 Java、Python、Kotlin JVM、Clojure。

- 卡片右下角 `CC n` 是文件或包内最高的函数复杂度；详情里按复杂度列出函数，点击跳到源码对应行。
- 上限取项目 `crap.toml` 中 `[gate] max_complexity`，没有则按 10；超过上限为红色，超过上限的 80% 为黄色。工具栏「复杂度」眼睛按钮可开关显示。
- 没装 crap 或语言不支持时不显示；`ARCH_VIEW_CRAP=off` 或 `--crap off` 可关闭。

用户关心复杂度或想加门禁时：`crap complexity . --top 20` 查看最复杂的函数；`crap init --max-complexity 12` 生成 `crap.toml`，`crap hook install` 安装提交钩子（会生成 `CRAP_GUIDE.md`，与 `crap.toml` 一起提交）。超标函数先说明原因和拆分方案，经用户同意再改代码。
