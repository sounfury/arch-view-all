# 架构说明与可视化

在目标项目目录操作；参数按需查看 `arch-view --help` 或 `arch-view <命令> --help`。

1. 检查目标项目根目录的 `ARCHITECTURE_TEMPLATE.md`：存在就读取，跳过 `init`；不存在才执行 `arch-view init .` 获取模板。按文件是否存在判断，无需额外的初始化标记。
2. 检查 `ARCHITECTURE.md`。不存在时读取[生成提示词](references/architecture-prompts.md)，按新老项目对应流程编写；已存在时轻量检查标题层级、Mermaid 数据流、子系统标识和三项实现状态。符合模板就直接查看，不重复生成；不符合时仅做必要适配，保留正文和有效人工状态，不整篇重写。需要补写内容时再读取生成提示词，缺失的业务事实列出供用户确认。
3. 文档准备好后，默认通过 `arch-view serve .` 打开网页界面。AI 自动化调用用持久或后台进程执行 `arch-view serve . --no-browser`，读取就绪输出中的实际地址并打开给用户，服务会常驻，不等待它退出。仅在用户明确要求分析或导出时用 `arch-view scan`，明确要求桌面界面时用 `arch-view desktop`。
4. 文档与代码不一致时说明差异，由用户决定更新文档还是调整代码。

用户询问或需要调整默认行为（如连线范围、语言、Python 解释器）时，读取[配置说明](references/configuration.md)。配置是工具安装目录下的全局 `.env`，不在用户项目中创建或读取配置文件。

保持文档简短，只维护项目背景、子系统职责和关键数据流；主要职责、边界或数据流变化时才更新。Mermaid 节点标识与子系统标题一致，探索链接单独填写实际代码包路径；数据流不等同于代码依赖。

网页的模块卡片与源码详情会自动读取文件头说明：文件最前面的 `;`、`#` 注释行，开头的 `/* */` 或 `/** */` 块注释（须在 `package`、`import` 之前），Python 模块文档字符串，以及 Clojure `ns` 文档字符串；`//` 行注释不读取，版权、许可证和编码声明会被忽略。目录只有一个源码文件时沿用该文件的说明；`ARCHITECTURE.md` 中绑定的子系统职责优先显示。新建文件或职责变化时，在文件头用一两句话写明职责，图才会更易读；整理老项目时，列出缺少说明的关键文件供用户决定是否补写，不擅自批量改业务代码。

实现状态必须写进 `ARCHITECTURE.md`。网页只读取文档并保存用户在单选框中的选择，不会按源码绑定自动补齐或改写。生成或补齐时：已有项目绑定实际代码的子系统默认“已完成”，没有任何代码绑定的子系统标“未完成”；新项目尚未开始的子系统也标“未完成”。保留已有有效人工标记，提醒用户在网页中标出例外，不逐项追问。项目新旧依据实际代码判断。生成文档不代表获准修改业务代码。详细规则见[生成提示词](references/architecture-prompts.md)。
